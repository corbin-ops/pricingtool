SECTION 04
Valuation Score — Dual Rating System
This section produces two independent scores (0–10) for two separate LandInsight-provided values: the county
Assessed Value and the LandInsight Market Land Value. Each is scored by comparing it to the user-entered
MV comp as a percentage. The ideal ratio is 50% — where the county/market value is exactly half of the
operator's comp — giving maximum negotiation leverage.
Inputs
  MV (Market Value) — entered by the operator in the Input MV block. This is the operator's own comp, not
pulled from any data source.
  Assessed Value — pulled from LandInsight (county assessor figure).
  Market Land Value — pulled from LandInsight (their proprietary land value estimate).
Scoring Formula — Piecewise Linear Interpolation
The score is calculated using an asymmetric bell curve, defined by anchor points. Given a percentage ratio
(value / MV * 100), the score is linearly interpolated between the two nearest anchor points.
ratio = (assessed_value / MV) * 100 /* or market_land_value / MV * 100 */
score = piecewise_linear_interpolation(ratio, ANCHOR_POINTS)
Anchor Points Table
These are the exact calibration points. The curve rises from the left, peaks at 50%, then drops more steeply on the right side
— reflecting that a high county value is worse than a low one (less negotiation room).

Implementation (JavaScript)
const SCORE_ANCHORS = [
  [0, 0], [15, 1], [25, 2.5], [30, 4.5], [50, 10],
  [70, 6.5], [80, 4], [90, 1], [100, 0], [115, 0]
];
function interpScore(pct) {
  if (pct <= 0 || pct >= 115) return 0;
  for (let i = 0; i < SCORE_ANCHORS.length - 1; i++) {
    const [x0, y0] = SCORE_ANCHORS[i];
    const [x1, y1] = SCORE_ANCHORS[i + 1];
    if (pct >= x0 && pct <= x1) {
      return y0 + (pct - x0) / (x1 - x0) * (y1 - y0);
    }
  }
  return 0;
}

SECTION 05
Acreage Intel & Survey Flag System
Compares the deeded acreage from the deed/title against the calculated acreage from LandInsight's GIS
measurement. When discrepancy exceeds a size-adjusted threshold, the system flags the parcel as needing a
survey. The threshold is not flat — it uses a power curve that decays with parcel size, because small absolute
gaps matter more on small parcels.
Survey Flag Threshold Formula
The maximum acceptable variance (as a percentage) is defined by a power curve fitted to the operator's
calibration data:
threshold_pct(acres) = 54 * acres^(-0.376)
min_acceptable_ac = deeded_acres * (1 - threshold_pct / 100)
Formula Derivation — Calibration Points
This curve was fitted to the following operator-provided anchor points using least-squares regression on a
power model (y = A * x^B):

--- PAGE 10 ---
const A = 54, B = -0.376;
function surveyThresholdPct(deededAcres) {
  return A * Math.pow(deededAcres, B);  // % variance allowed
}
function minAcceptableAcres(deededAcres) {
  const t = surveyThresholdPct(deededAcres);
  return deededAcres * (1 - t / 100);
}
function surveyFlag(deededAcres, liCalcAcres) {
  const minAc = minAcceptableAcres(deededAcres);
  if (liCalcAcres < minAc)          return 'flag';
  if (liCalcAcres < minAc * 1.15)   return 'watch';
  return 'normal';
}
Negotiation Use
A survey flag is a negotiation lever. When triggered, the interface suggests asking: 'When was the last time you
had this property surveyed?' A significant discrepancy opens a conversation about adjusting the offer
downward to reflect the actual measured acreage, or making the deal contingent on a survey.

SECTION 07
Input MV — Operator Market Value Entry
The Input MV block is the single source of truth for all pricing math in the dashboard. The operator enters their
own market value comp here — derived from comparable sales research, LandInsight data, and judgment. This
is NOT the LandInsight market land value; it is the operator's independent valuation.
  MV drives: Offer Range · Max Offer · Est. Profit · Valuation Score · Price/Acre
Cascading Updates
Every downstream calculation recalculates in real time on every keystroke using an oninput event listener. The
update chain is:
  1. MV changes
  2. updateAll(mv) fires
  3. Market value display, price/acre, offer range (50-70%) recalculate
  4. Max offer f(MV) recalculates
  5. Net proceeds g(MV) recalculates
  6. Estimated profit = net proceeds - max offer recalculates
  7. Valuation score rings for AV and MLV recalculate (ratio = value / new MV)
Implementation
document.getElementById('mv-input').addEventListener('input', function() {
  updateAll(parseFloat(this.value) || 0);
});

SECTION 08
Price Pulse & Subdivide Curve
This is the primary chart section in the right column. It shows a power-law price-per-acre curve for the county
market, marks the subject parcel on that curve, and classifies the county as Subdividable, Semi-subdividable,
or Non-subdividable based on the curve's exponent. A split preview shows what happens to $/ac if the parcel is
divided into 2, 3, 4, or 5 lots.
The Power Curve Formula
Each county market is described by a formula of the form:
price_per_acre(acres) = COEFF * acres^EXPONENT
The operator selects the appropriate formula for the county being analyzed. The formula is calibrated from
comparable sales data. The current working formula is:
price_per_acre(acres) = 18,781 * acres^(-0.58)

The Double-Your-Money Threshold
The core test is whether splitting the parcel can double the price per acre. The 2x line on the chart is drawn at
double the subject parcel's current $/ac. Any split scenario whose resulting lot $/ac lands above this line is a
viable double-your-money split.
subject_ppa = COEFF * subject_acres^EXPONENT
double_line = subject_ppa * 2
split_lot_ppa = COEFF * (subject_acres / n_lots)^EXPONENT
multiplier = split_lot_ppa / subject_ppa
Split Preview Cards
Four cards are generated for 2-lot, 3-lot, 4-lot, and 5-lot splits. Each card shows the lot size (acres each), the
resulting $/ac from the curve formula, and the multiplier vs. the whole parcel. Cards with multiplier >= 2.0 are
highlighted green.
function buildSplits(subjectAcres, coeff, exp) {
  const basePPA = coeff * Math.pow(subjectAcres, exp);
  [2, 3, 4, 5].forEach(n => {
    const lotAc  = subjectAcres / n;
    const lotPPA = coeff * Math.pow(lotAc, exp);
    const mult   = lotPPA / basePPA;
    // render card — highlight green if mult >= 2.0
  });
}

SECTION 09
Market Anchor — Pricing Math
Four stat boxes arranged in a 2x2 grid below the chart. All values derive from the operator's MV input. The
realtor rate is also editable inline.
Box 1 — Market Value (MV) with Price Per Acre
market_value = MV (operator input — no formula)
price_per_acre = MV / deeded_acres
Price per acre displays smaller, to the right of the MV figure, inside the same box.
Box 2 — Offer Range (50–70%)
offer_low = MV * 0.50
offer_high = MV * 0.70
Displays as a range: '$84,000 – $117,600'. This is the operator's working offer window.
Box 3 — Max Offer f(MV)
The absolute maximum offer, calculated using an exponential saturation formula. As MV grows, the percentage
of MV that can be offered grows toward an asymptote (never reaching 92%). The output is a percentage;
multiply by MV to get a dollar figure.
f(MV) = 92.0 - 55.0 * e^( -0.00161 * MV^0.620 )
max_offer_pct = f(MV)
max_offer_dollar = MV * (max_offer_pct / 100)
Example at MV = $168,000:
  f(168000) = 92.0 - 55.0 * e^(-0.00161 * 168000^0.620)
   = 92.0 - 55.0 * e^(-0.00161 * 1617.3)
   = 92.0 - 55.0 * e^(-2.604)
   = 92.0 - 55.0 * 0.0739
   = 92.0 - 4.06 = 87.94% of MV
  max_offer = $168,000 * 0.8794 = $147,745
Box 4 — Estimated Profit g(MV)


--- PAGE 17 ---
Net proceeds after realtor fees and closing costs, minus the max offer. The g(MV) formula returns net proceeds
as a percentage of MV, accounting for a variable realtor rate and a fixed closing cost assumption of $2,500.
g(MV) = (1 - realtor_rate) * 100 - (2,500 / MV) * 100
net_proceeds = MV * (g(MV) / 100)
estimated_profit = net_proceeds - max_offer_dollar
Example at MV = $168,000, realtor_rate = 3% (0.03):
  g(168000) = (1 - 0.03) * 100 - (2500 / 168000) * 100
   = 97.0 - 1.488 = 95.51% of MV
  net_proceeds = $168,000 * 0.9551 = $160,457
  estimated_profit = $160,457 - $147,745 = $12,712
The realtor rate input defaults to 3% (land deals typically have one side only) but is editable by the operator. Changing it
updates the profit figure in real time.
Implementation (JavaScript)
function fOffer(mv) {
  return 92.0 - 55.0 * Math.exp(-0.00161 * Math.pow(mv, 0.620));
}
function gNet(mv, realtorRatePct) {
  return (1 - realtorRatePct / 100) * 100 - (2500 / mv) * 100;
}
function calcProfit(mv, realtorRatePct) {
  const maxOffer    = mv * (fOffer(mv) / 100);
  const netProceeds = mv * (gNet(mv, realtorRatePct) / 100);
  return netProceeds - maxOffer;   // target: ~$10,000-$15,000
}

SECTION 10
Counter Craft — AI Negotiation Tool
A textarea where the operator types a brief negotiation point or context note. On clicking 'Generate counter', the
input is combined with the parcel's known context (tax delinquency, ownership length, acreage discrepancy,
subdivide status) and sent to the Claude API to generate a tailored negotiation script.
Prompt Construction
The prompt passed to the API should include all available parcel signals as context so the AI can generate a
specific, relevant response rather than a generic one. Structure:
const prompt = `
  You are helping a land acquisition specialist craft a
  negotiation counter. Here is the parcel context:
  - Tax delinquent: ${taxDelinquent}
  - Back taxes: ${backTaxes}
  - Ownership length: ${ownershipYears} years
  - Family transfer: ${familyTransfer}
  - Owner proximity: ${ownerProximity}
  - Acreage discrepancy: ${discrepancyPct}%
  - Survey flag: ${surveyFlag}
  - County subdivide status: ${subdivideStatus}
  - Market value (op comp): $${mv}
  - Max offer: $${maxOffer}
  Operator's negotiation point: ${operatorInput}
  Write a confident, empathetic negotiation script the
  operator can use verbatim or adapt. Reference specific
  signals above. Keep it conversational, not salesy.
`
